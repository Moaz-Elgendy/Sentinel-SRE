From alert to verified recovery.

Sentinel investigates Kubernetes failures, applies only pre-approved fixes, and checks that the system really recovered.

An alert says something is wrong. It does not say what to do.

Between the alarm and a working system there is slow manual work: finding the cause, choosing a safe fix, proving it worked. Sentinel connects those steps and keeps a record of each one. Its rule is simple.

The model advises.
Policy authorizes.
Typed executors act.
Recovery checks decide whether it worked.

An AI model can suggest a cause, but it never gets to run anything on its own. A fixed rulebook decides what is allowed, and a separate check confirms the fix actually helped.

Ten steps, every incident.

Repeat alerts for the same problem join the open incident instead of starting duplicate fixes. If no safe known action exists, Sentinel escalates with its evidence instead of guessing.

Autonomy with a short leash.

Everything is denied unless a rule explicitly allows it. The limits below are the defaults in source and are configurable.

Each action has its own confidence bar

Sentinel must be at least this sure before it acts without a human. Rollback is held to the highest standard because it is the most disruptive.

0.95Roll back
0.90Restart
0.90Scale 1 to 3
0.90Reset fault

For unfamiliar failures, a human signs off

Deep investigation is read-only: at most 6 turns, 8 tool calls and 90 seconds. It can only propose one of six typed changes, needs 0.97 confidence, and always waits for explicit authorization. There is no free-form shell.

Honest about what it is.

Working today

  • Scoped remediation. Restart, roll back, scale and reset, each behind policy.
  • Deep investigation. Read-only reasoning with human authorization.
  • Recovery validation. Health, errors, latency, CPU and memory, not just a successful command.
  • Full audit trail. Replay stored incidents to see what Sentinel would decide.
  • AWS delivery. Terraform, OIDC, ECR and SSM end to end.

Still ahead

  • More environments. One active environment per process today.
  • High availability. Single replica, SQLite and local-disk databases.
  • Production hardening. TLS, credential rotation, remote Terraform state.
  • Wider autonomy. New actions need new explicit policies and executors.
  • Pinned Sentinel deploys. The control plane pulls latest for now.

A working prototype on a single workload node, not production infrastructure. Learning from outcomes only makes Sentinel more cautious. It is not model training.
